# Лабораторная работа №7 – Консольное приложение для управления персонажами RPG

## Цель работы

Объединить знания, полученные в предыдущих лабораторных работах (№1–№6), в единое работающее консольное приложение. Реализовать интерактивный CLI-интерфейс с системой меню, позволяющий управлять коллекцией персонажей RPG, с возможностью добавления, удаления, поиска, фильтрации, сортировки, а также сохранения и загрузки данных.

## Предметная область

Приложение предназначено для управления персонажами в RPG. Поддерживаются четыре типа персонажей:

- **Обычный персонаж** – базовый класс с основными характеристиками.
- **Воин** – дополнительно имеет оружие и рейтинг брони.
- **Маг** – дополнительно имеет школу магии, количество маны и список изученных заклинаний.
- **Лучник** – дополнительно имеет тип лука, точность и количество стрел.

Каждый персонаж обладает следующими базовыми характеристиками:
- Имя (уникальный идентификатор)
- Здоровье (0–100)
- Выносливость (0–40)
- Сила (1–60)
- Интеллект (1–80)

## Функциональные возможности

### Управление коллекцией
- Добавление нового персонажа с выбором класса
- Просмотр всех персонажей в форматированной таблице
- Удаление персонажа по имени (с подтверждением)
- Полная очистка коллекции (с подтверждением)

### Поиск и фильтрация
- Поиск персонажа по имени
- Фильтрация по классу (Воин/Маг/Лучник)
- Фильтрация по здоровью (здоровые > 50)
- Фильтрация по силе (сильные > 30)
- Фильтрация по диапазону здоровья
- Фильтрация по диапазону силы

### Сортировка
Поддерживается сортировка по следующим критериям:
- По имени
- По здоровью
- По силе
- По интеллекту
- По выносливости
- По классу
- По рейтингу силы
- По дате создания

Для каждого критерия доступна сортировка как по возрастанию, так и по убыванию.

### Статистика
Отображается следующая информация о коллекции:
- Общее количество персонажей
- Среднее здоровье
- Средняя сила
- Средний интеллект
- Количество воинов, магов и лучников

### Сохранение и загрузка данных
- Автоматическая загрузка данных из JSON-файла при запуске программы
- Автоматическое сохранение данных в JSON-файл при выходе из программы
- Данные сохраняются в структурированном формате с сохранением всей информации о персонажах

## Архитектура приложения

Приложение построено по трёхслойной архитектуре:

1. **Слой представления (cli.py)** – отвечает за взаимодействие с пользователем: вывод меню, ввод данных, отображение результатов. Не содержит бизнес-логики.

2. **Слой бизнес-логики (app.py)** – содержит основную логику работы с коллекцией: добавление, удаление, поиск, фильтрацию, сортировку и подсчёт статистики.

3. **Слой данных (models.py)** – содержит классы персонажей и класс коллекции, а также методы для работы с ними.

Дополнительные модули:
- **exceptions.py** – собственные исключения для обработки ошибок предметной области
- **storage.py** – функции для сохранения и загрузки данных в JSON-формате
- **main.py** – точка входа в приложение

## Обработка ошибок

Приложение корректно обрабатывает следующие ошибочные ситуации:
- Ввод некорректных данных (буквы вместо чисел, числа вне допустимых диапазонов)
- Попытка добавить персонажа с уже существующим именем
- Попытка удалить или найти несуществующего персонажа
- Выбор несуществующего пункта меню
- Выбор неверного типа класса при фильтрации

Для обработки этих ситуаций используются как стандартные исключения Python, так и собственные исключения, определённые в модуле exceptions.py.
